The editable source artwork is `src/assets/logo.svg`. Violet occupies 25% of the combined filled area, excluding transparency. Its two outer diagonal edges align with the main diamond's extended edges, meeting at the virtual right tip `(123, 64)`. The body path has 8px outer corners, rounded 4px tips beside the insert, and a rounded 19px inner notch. The violet insert has a 10px left corner and 4px corners elsewhere. Its left curve and facing diagonal edges have 9px clearance from the body in the 128px viewBox. The violet fill is `#5f3afc`. Edit the SVG and run `pnpm icons:generate` to regenerate all 12 PNGs. Generated PNGs should not be edited directly.

`light/` contains the charcoal-and-violet mark for light backgrounds. `dark/` sets the SVG's `data-body` shape to light ink before rasterizing; the violet shape and fill are identical in both themes. Every size is rendered from SVG. The options and popup select these assets using the page's `.dark` theme class. Both pages currently use a dark theme. The favicons and root README select the same variants using `prefers-color-scheme`.

The browser action follows the `prefers-color-scheme` preference reported by visible options, popup, and top-level HTTP/HTTPS pages. These pages inherit Chrome's appearance setting, which can differ from the OS theme reported by an offscreen document. Reports use extension messaging in the isolated content script, without reading the website's styles or changing its theme. Background tabs, subframes, and incognito websites cannot set the global icon. Successful updates are acknowledged; failed reports retry. Repeated media-query events for an unchanged theme send no further messages. Becoming visible or receiving focus reports the current theme again because another page may have changed the global icon. Development previews skip the reporter when extension APIs are unavailable. The last reported browser theme is kept in session storage so worker restarts and offscreen reports cannot replace it with the OS theme.

Until a browser page reports its theme, an offscreen observer supplies the OS preference. It samples once per second because Chromium defers media-query change events in hidden documents; timer throttling can delay these checks. The `offscreen` permission is used only for this fallback observer. Chrome's [Offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen) supports the `MATCH_MEDIA` reason. If only restricted pages such as `chrome://settings` are open, the last browser theme remains in use until a supported website, options page, or popup becomes visible. This also applies to later OS changes while Chrome uses Device mode, because the observer cannot distinguish Device mode from an explicit Chrome appearance setting. After reloading the extension, reload existing website tabs to load the reporter.

The PNGs directly in this directory use a filled light mark with a thin charcoal inner edge, keeping the silhouette visible on both light and dark backgrounds. They are the manifest fallback before theme synchronization or if it fails, and are also used by Chrome's extension management page. Chrome's [manifest icons](https://developer.chrome.com/docs/extensions/reference/manifest/icons) are separate from the toolbar's runtime icon, so the management card uses this static artwork. All variants have transparent backgrounds. Theme-specific icons use no keyline. Custom browser colors can differ from the reported light/dark preference.

To regenerate all variants in four sizes from the project root, run `pnpm icons:generate`. The generator uses the project's Playwright dependency and requires its Chromium browser to be installed with `pnpm exec playwright install chromium`.
