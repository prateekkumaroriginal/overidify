# How Requestly modifies responses

Checked 2026-10-14 against Requestly's public source. The old requestly/requestly repository is now a community hub; interceptor code lives in requestly/interceptor. All extension source links below pin commit 6209537426f7224303b0652969fdca474b9a478a. This is source inspection, not a test of the published extension binary.

## Finding

Requestly's browser extension uses the same page-level fetch/XHR wrapping considered earlier. It changes the response application JavaScript receives. It does not establish a way to put arbitrary mocked responses into native Chrome Network without additional setup. Requestly's documentation explicitly explains that the browser's Network panel shows the original response. [Official limitation](https://interceptor-docs.requestly.com/troubleshoot/http-rules/rule-changes-not-reflecting-in-chrome-devtools)

## Code evidence

- The extension registers its AJAX interceptor in the MAIN world, at document_start, across matching HTTP(S) frames. It also injects cached rule settings into the MAIN world. [clientHandler.ts, registration](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/service-worker/services/clientHandler.ts#L14), [settings injection](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/service-worker/services/clientHandler.ts#L129)
- fetch.js captures the original fetch and replaces the global function. A matching static bypass rule avoids invoking the original fetch; otherwise it awaits the native call. It then returns a new Response containing the configured body and configured status, with a native-status/200 fallback. Bodyless statuses 204, 205, and 304 receive null body. [fetch.js, wrapper](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/fetch.js#L19), [bypass/live branch](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/fetch.js#L107), [constructed response](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/fetch.js#L213)
- xhr.js replaces XMLHttpRequest and creates a second native XHR behind the object returned to the application. For matched calls, it substitutes status/body getters and dispatches synthetic ready-state/load events. Bypass simulates completion; call-server invokes send on the internal native object. [xhr.js, substituted properties](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/xhr.js#L80), [constructor](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/xhr.js#L261), [server-mode branch](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/xhr.js#L373)
- serveWithoutRequest applies only to static response rules. Response matching chooses the last applicable rule from the page's cached rules. [utils.js](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/utils.js#L187)

## Differences from accepted Overidify behavior

Do not copy these Requestly choices as product requirements:

- Its fetch wrapper catches native failures when a response rule exists and can still return the mock with status 200. Overidify must preserve call-server failure. The outer catch can also retry the original fetch after a wrapper error. [fetch.js failure handling](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/fetch.js#L135)
- Its fetch bypass headers contain generated Content-Type based on body JSON validity; its live branch reuses native response headers. Those branches do not replace headers with an arbitrary complete configured list. [fetch.js headers](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/fetch.js#L104)
- Synchronous XHR passes through. Static modification does not replace blob, arraybuffer, or document responses. XHR bypass exposes generated Content-Type, while live header getters forward to the native object. Overidify has not accepted those exclusions or header policies. [xhr.js synchronous pass-through](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/xhr.js#L309), [response-type limit](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/xhr.js#L135), [bypass headers](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/ajaxRequestInterceptor/xhr.js#L28)

## Inspector versus desktop proxy

Requestly includes its own DevTools page and network recorder. The recorder captures XHR/fetch bodies in a MAIN-world script and forwards them for extension recording. This is an additional inspection interface, not a write API for native Chrome Network. [Chrome manifest](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/manifest.chrome.json#L38), [networkBodyRecorder.js](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/page-scripts/networkBodyRecorder.js#L3)

Desktop connection is a separate route. The extension's applyProxy calls chrome.proxy.settings.set with fixed_servers, configuring the desktop helper's host and port. Its docs describe proxy configuration and certificate installation, including connection from an existing browser profile through the extension popup. That setup explains how actual HTTP(S) responses can change before the browser records them. It does not prove an extension-only workaround. [proxy.ts](https://github.com/requestly/interceptor/blob/6209537426f7224303b0652969fdca474b9a478a/browser-extension/mv3/src/service-worker/services/proxy.ts#L11), [desktop browser setup](https://interceptor-docs.requestly.com/interceptor/desktop-app/browser-interception)

Requestly confirms that convenient extension-only response mocking and native Network replacement are different capabilities. After this comparison, the user accepted extension-only mocking and superseded native Network replacement in [ADR 0007](../network-rules/adr/0007-extension-only-page-interception.md).
